LOCAL PROJECT REFERENCE

ReconcileOS source guide

Compare recorded orders, payments, and settlement evidence, then document human decisions. This offline reference follows actual implementation paths. It does not record a completed learner tour or final readiness.

Reference route: confirm, reconcile, inspect

1. Confirm selected rowsAPI validates the preview revision and stores source records atomically.
2. Freeze and calculateA stored snapshot feeds pure integer rules and allocation checks.
3. Inspect the resultThe browser displays API values, decision rules, and original source cells.
  1. backend/app/services/imports/service.py, confirm_batch: inserts selected validated records and their audit event together. Mapping and corrections preserve original cells.
  2. backend/app/services/reconciliation/service.py, create_run, and backend/app/services/reconciliation/engine.py, reconcile: capture confirmed inputs and fee rules, calculate deterministic relationships, and persist complete results with allocation uniqueness.
  3. frontend/src/features/reconciliation/ReconciliationPage.tsx and frontend/src/components/EvidenceDialog.tsx: show current accepted relationships, cases, rules, original source values, and import provenance. The frontend formats integer strings with BigInt; it does not decide financial matches.
How this is verified

backend/tests/test_settlements.py, test_full_synthetic_manifest_through_real_api, imports all three files through the actual API and compares summaries and exact relationships with an independently specified manifest. frontend/e2e/workflow.spec.ts exercises real local services, evidence inspection, review actions, reload, and an actual CSV download.

A practice to reuse

The first import workflow rejected ordinary exports. Actual learner feedback changed the acceptance criterion: recognize common CSV/Excel files and headings, but retain explicit review for financial ambiguity. The implementation in mapping.py, checks in backend/tests/test_flexible_imports.py, and real-workbook browser tests turn that feedback into observable behavior.

For another project, start with a real awkward input and an expected result. Preserve the original evidence, test the user-visible decision, and keep mechanical verification separate from the user's final review. This is a project-grounded reference, not a claim about anyone's learning.

Run the app again

From the repository root, use two PowerShell terminals after installing dependencies and applying migrations as documented in README.md.

cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
cd frontend
npm.cmd run dev

Open http://127.0.0.1:5173. The default SQLite file is backend/data/reconcileos.db. Use a separate database for synthetic demonstrations. No Docker, live financial integrations, AWS deployment, or public authentication is part of this local mode.

This guide is versioned alongside the code. Use git log -1 -- devpost/app-map.html to identify its checkpoint. Paths can drift after later changes. The guide has no scripts, network assets, analytics, credentials, or private learner context.
